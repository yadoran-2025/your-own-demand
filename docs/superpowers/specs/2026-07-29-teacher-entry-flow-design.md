# 교사용 첫 진입 흐름 설계

## 목표

교사용 대시보드의 단일 `방 이름` 입력을 Golden UI `v1.0.0`과 같은 첫 진입 흐름으로 교체한다.

`지역·학교·학년 설정 → 학급 선택 → 차시 선택 → 기존 대시보드`

현재 교사 대시보드, 설문 편집, 응답·결과 화면, 학생 QR 진입의 데이터 격리는 유지한다.

## 화면과 동작

### 1. 학교·학년 설정

- 교사용 방이 없을 때 `/teacher`에서 표시한다.
- 골든 UI와 같은 좌측 소개 영역과 우측 입력 패널을 사용한다.
- 필수 입력: `지역`, `학교`, `학년`.
- 제출 버튼: `학교와 학년 만들기 / 입장`.
- 입력값은 브라우저 localStorage에 교사용 작업 공간으로 저장한다.

### 2. 학급 선택

- 기존 학급 카드를 표시한다.
- `새 학급` 카드에서 학급명을 입력하고 추가한다.
- 학급 카드 선택 시 차시 선택으로 이동한다.
- 삭제는 명시적 확인 후 가능하다.

### 3. 차시 선택

- 현재 수요곡선 설문 목록을 차시 카드로 표시한다.
- 카드마다 `대시보드`와 `QR 열기`를 둔다.
- 기존 기본 설문 생성과 설문 편집 기능을 재사용한다.

### 4. 대시보드와 QR

- 선택한 학급·차시로 기존 교사용 대시보드를 연다.
- QR과 학생 링크는 현재처럼 학생 화면으로 직접 이동한다.
- 교사용 `나가기`는 차시 선택으로 돌아간다. 별도 뒤로가기 버튼은 추가하지 않는다.

## 저장 및 호환성

- 새 localStorage 작업 공간에는 `region`, `school`, `grade`, `classes`, `selectedClass`, `selectedLessonId`를 둔다.
- 서버와 기존 클라이언트 API는 계속 단일 `roomName`을 받는다.
- 선택 완료 시 내부 방 키를 `지역 / 학교 / 학년 / 학급` 형태로 생성해 기존 `roomName` 위치에 전달한다.
- 기존 `demand-app-teacher-room` 값은 그대로 읽고 사용한다. 이미 만든 방의 설문·응답은 이동하거나 삭제하지 않는다.
- 학생 URL은 생성된 내부 방 키를 계속 포함하므로 기존 학생 입장 경로와 데이터 분리가 유지된다.

## 구현 범위

- `lib`: 교사용 작업 공간 저장, 방 키 생성, 기존 단일 방 값 호환.
- `components`: 첫 진입, 학급 선택, 차시 선택 화면.
- `app/teacher`: 선택 상태에 따른 단계 렌더링과 기존 대시보드 연결.
- CSS: Golden UI `v1.0.0`의 진입·카드·반응형 구조를 현재 앱의 클래스 범위 안에서 적용.

## 제외 범위

- Firebase 데이터 스키마 변경 및 기존 데이터 마이그레이션.
- 학생 신원, 분석, 권한 모델 변경.
- Golden UI 저장소 자체 업데이트.

## 검증

- `npm run typecheck`
- `npm run lint`
- `npm run build`
- 로컬 브라우저에서 지역·학교·학년 입력, 학급 추가·삭제, 차시 선택, 대시보드 나가기, 학생 URL의 방 키 전달을 확인한다.
